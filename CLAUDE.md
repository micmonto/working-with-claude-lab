# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A workshop repository wrapped around a sample app, **ops-dashboard**: a Spring Boot read-only JSON API over PostgreSQL plus a vanilla-JavaScript dashboard page. `workshop/` and `docs/` hold the lab instructions, tickets (`docs/tickets/TODO-23x.md`) and example hooks, agents and skills; the app itself is under `src/`.

## Commands

```bash
# Run (PostgreSQL, the default profile)
docker compose up -d db
./mvnw spring-boot:run                              # http://localhost:8080

# Run without Docker (in-memory H2, same migrations and seed)
SPRING_PROFILES_ACTIVE=demo ./mvnw spring-boot:run

# Java tests: 25 (JUnit 5, MockMvc, H2; no database needed)
./mvnw test
./mvnw test -Dtest=DashboardRepositoryTest
./mvnw test -Dtest=DashboardRepositoryTest#kpisForTheLast30DaysMatchTheAnswerKey

# Frontend tests: 66 (Jest + jsdom); run `npm install` once first
npm test
npx jest src/test/javascript/range.test.js
npx jest -t "the 7-day preset"
```

There is no linter and no frontend build step. `docker compose down -v` wipes the database.

## Rules specific to this repo

- **`pom.xml` dependencies are frozen.** Changes require a CHG ticket; do not add or bump dependencies.
- **Every element `id` in `index.html` must be listed in `REGISTERED_IDS`** in `src/test/javascript/setup/loadApp.js`. `harness.test.js` fails otherwise, in both directions.
- **Before reporting work as done:** run both `./mvnw test` and `npm test` and report both counts.
- When working a ticket, the ticket file in `docs/tickets/` is the source of truth.

## Architecture

### Backend (`src/main/java/com/marlowefinch/ops/`)

- Thin `@RestController`s, one per resource, delegate to two repositories that hold plain SQL through Spring JDBC. There is no JPA and no service layer; responses are Java records.
- All endpoints are `GET` under `/api`. Range endpoints take `from` and `to` as strings and pass them to `DateRange.resolve`, which defaults to the last 30 days ending today.
- **There is deliberately no input validation**: a malformed date is a 500, `from` after `to` returns empty results, `limit` is unchecked. This is ticket TODO-232, and `DashboardControllerTest.malformedFromCurrentlyProducesA5xx` asserts the current behaviour, so it must change with that ticket.
- **"Today" is pinned to 2026-09-21** through the `ops.today` property and the `Clock` bean in `ClockConfig`. Use the injected `Clock` for anything date-related; never `LocalDate.now()`.
- Schema and data come from Flyway migrations in `src/main/resources/db/migration/`. `V2__seed.sql` is generated by `tools/make_seed.py`, which also writes `docs/data/deliveries-last-30-days.csv` and the git-ignored answer key; do not edit the seed by hand.
- Two profiles: `postgres` (default, Docker Compose database) and `demo` (H2 in PostgreSQL mode). SQL must run on both, because the tests always use `demo`.

### Frontend (`src/main/resources/static/`)

- `app.js` is a single IIFE with three sections: the API client (`createApi`), pure helpers (`formatRate`, `formatMoney`, `barWidths`, `applyPreset`, `daysUntil`), and `initApp(document, fetchImpl)`, which wires the DOM and returns `{ ready, state, load, selectPreset, api }`.
- It exports through `module.exports` under Jest and as `window.OpsDashboard` in the browser, where it starts itself on `DOMContentLoaded`. `document` and `fetch` are injected, which is what makes it testable.
- On load it calls `/api/health` first to learn "today", then the four range endpoints and `/api/vendors`. Charts are inline SVG.

### Tests

The two suites are independent and meet only at the API's JSON contract.

- **Java:** every test class is `@SpringBootTest` with `@ActiveProfiles("demo")`, so it boots the full context against H2 with the real migrations and seed. Expected figures (651 deliveries, 0.937 on-time rate, 624 orders, and so on) are hard-coded from the seed; regenerating the seed breaks them.
- **Frontend:** tests go through `loadApp(overrides)` in `setup/loadApp.js`, which mounts the real `index.html` body in jsdom, swaps `fetch` for an in-memory fake API serving `FIXTURES`, and awaits `app.ready`. Pass `overrides` to replace a fixture or `{ failing: ['/api/kpis'] }` to make paths return 500; `api.calls` records every request.
- The Jest fixtures are hand-copied to mirror the real API responses. Nothing enforces that, so a change to an endpoint's JSON shape needs both the Java tests and `FIXTURES` updated.

## MCP

`.mcp.json` registers a read-only `postgres` MCP server pointing at the compose database (`postgresql://ops:ops@localhost:5432/ops`). It fails to connect when the database is not running; `docs/data/deliveries-last-30-days.csv` is the fallback for the same data.
